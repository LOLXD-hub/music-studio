# Architecture

```
            AI client (Claude Code, Codex, Antigravity, ...)
                  │  MCP: Streamable HTTP (token) or stdio bridge
                  ▼
        ┌──────────────────────── main process ────────────────────────┐
        │  mcp/server.ts   19 tools, zod schemas, sessions             │
        │  core/studio.ts  project state, undo, activity, feedback     │
        │  core/tools-*.ts every action = one function on the studio   │
        │  core/render-worker.ts  offline render + analysis (threads)  │
        └───────────────┬──────────────────────────────┬──────────────┘
          patches/events│                              │ file I/O (WAV, FLAC, MP3, MIDI, FFmpeg decode)
                        ▼                              ▼
        renderer (Preact UI) ── AudioWorklet ── engine/Engine      examples, projects, sound library
```

## One engine for hearing and exporting

`src/engine/engine.ts` is a block-based renderer: tracks, instruments, inserts, sends, buses, sidechain, automation and a tempo map. The app runs it in an AudioWorklet for playback. Export, "listen" (analysis), stems and the demos run the same class offline in a worker thread. There is no second implementation, so a mixdown is the same signal you heard.

Instruments are in `src/engine/instruments`:

| Engine | Used for | Method |
|---|---|---|
| `piano` | pianos | modal synthesis: inharmonic partials, two-stage decay, hammer noise, sympathetic body |
| `mallet` | marimba, vibes, bells, kalimba | modal synthesis with per-mode decay |
| `plucked` | guitars, harp, bass | Karplus-Strong strings with pick position and body filtering |
| `wind_string` | strings, brass, winds, choir, pads | source-filter voices: vibrato, brightness that follows dynamics, legato mono, articulations |
| `organ` | tonewheel organ | drawbars, key click, Leslie |
| `fm` | electric piano, FM bells and bass | 4-operator FM |
| `subsynth` | leads, pads, basses | PolyBLEP oscillators, SVF and ladder filters, unison |
| `drums` | kits | synthesized drums with round-robin variation and hi-hat choke |
| `sampler` | your samples | multi-zone, interpolated playback |

`calibration.ts` is generated by `tools/calibrate.ts`. It stores a loudness trim per preset so that a default velocity gives similar levels across instruments.

## Studio state

`Studio` owns the project. `mutate(label, fn)` runs `fn` on a structured clone, commits it atomically, pushes an undo step, and sends the UI a patch of only the tracks that changed. Tools call `mutate`; the UI calls tools through IPC. A mutation from MCP and a mutation from a click take the same path, so both show up in the activity feed and both can be undone.

## The agent loop, seen from the app

- `agent` tool actions set the status (listening, building, loading, thinking, mixing). The top-left Clawd follows it, and idles back to asleep when nothing has called for a while.
- `feedback` items (messages, pins with a track and a bar, ratings) are queued by the UI. The agent reads them with `agent feedback` and replies with `agent reply`.
- `listen` renders offline and returns numbers and a picture; `critique` runs rule-based checks (`src/theory/critic.ts`) on notes and on per-track render statistics.

## Theory toolkit

`src/theory` has roman-numeral analysis, voice-led voicings, a progression library with a functional walk, melody generation from a developed motif, bass, comping and drum pattern generators, humanization, performance rules per instrument family (pedal, expression, vibrato, strums, legato) and song forms.

## Sound effects

`src/sfx/families.ts` defines parametric families (a laser, a door, a riser, rain, an UI blip). `catalog.ts` expands each into variants, which gives 1256 built-in sounds. `core/sfxlib.ts` is the user library: imports, additions, hides and edits live next to the built-ins as overrides, so a built-in can be restored.

## Security of the MCP endpoint

The server binds to `127.0.0.1`, requires a random bearer token, checks the Host and Origin headers (DNS rebinding), and keeps per-client sessions. The token is written to `.endpoint.json` in the data folder, which the stdio bridge reads.

## Where FFmpeg is used

Only in `src/core/audioio.ts`: decoding formats the app cannot read natively (OGG, M4A, AAC, Opus, AIFF) and encoding OGG, M4A and Opus. WAV, FLAC and MP3 are read and written without it. `tools/compare-ffmpeg.ts` calls it separately to build the comparison baseline.
